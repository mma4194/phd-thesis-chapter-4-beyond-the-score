# Method and source lineage

This package was reconstructed from the six requested archives after the earlier workspace failed. Personal-context retrieval recovered the outstanding preparation bug and discrepancy leads, but did not recover a saved final implementation. The implementation here is therefore a new portable assembly of the actual archived scientific code, not a claim that the lost workspace was recovered byte for byte.

## Scientific implementation retained

The original split and embargo rules, seeds, task definitions, model families, observation masks, predictor imputations, generated join exclusions, matched-training counts, bootstrap methods, source-health contracts, and failed outcomes are preserved. Residential and external aggregation orders intentionally differ, exactly as in the supplied code. Equal family weighting does not make their within-family mean and median operations interchangeable.

The corrected residential entry point refits admission on the fixed cards and all matching/P0/utility computations used by its reported result tables. It does not recreate the complete 640-card exploratory search from scratch. The historical candidate ledger is checked separately. The original canonical supplementary controls continue to use their frozen historical cards and licences. Their results must not replace corrected primary results.

The external raw preparation already contained reviewed adaptations from the deleted historical workflow: session intersection, whole bins, explicit masks, corrected raw timestamps, fresh origin-local matching, and the complete-prefix policy. Those adaptations are retained and recorded. The current reported reconstructed preparation has 28,752 rows and 64 value features. Its agreement with the reported reconstructed experiment is distinct from restoration of an earlier missing canonical dataset.

## Packaging changes

1. A single notebook now launches each scientific stage in its own pinned environment.
2. The historical external module name was changed to `external_rebuild` in active imports. Source identities and expected input/data hashes are retained.
3. Preparation completion binds immutable tables and copies of input checks, not live evaluation progress.
4. Exact supplementary printed-value and population comparisons were added without changing references.
5. Supplementary source cells are executed through explicit path bindings. Bootstrap/path-discovery cells are not run. `provenance/supplementary_source_map.json` records original cell hashes and which cells remain active.
6. The temporal-only diagnostic reads the same first 70,000 TEST rows in the same protocol feature scope one column at a time. It applies the canonical float32 conversion before non-finite-to-zero replacement. All 20 condition/seed rows are compared against the original output. This avoids unnecessary full-matrix allocation and does not change the diagnostic sample.
7. New execution reports and historic verification reports are stored separately. New runs do not import previous result folders as completed checkpoints.

No threshold, task, model, seed, or comparison tolerance was changed to obtain agreement. Documentation describes software and historical evidence boundaries directly, without journal-specific submission instructions.
